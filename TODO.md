# CampusGuide delivery outcomes

## 1. Site-wide information architecture and navigation
- [x] The website presents five linked sections: Home, About Us, Academic Programmes, Campus Life, and Contact Us.
- [x] A reusable header, primary navigation, and footer appear across the site with clear active-section highlighting and working links.
- [x] Every section is reachable from every other section in one click, and direct route URLs work in the browser.

## 2. Home experience
- [x] The Home route includes a campus-focused hero, a clear headline and CTA, quick links to the four other sections, and an introductory overview of the sample institution.
- [x] The home content clearly identifies the institution copy as sample content where appropriate.

## 3. About Us content
- [x] The About Us route presents institutional background, mission, vision, core values, and key facts and figures.

## 4. Academic Programmes content
- [x] The Academic Programmes route presents structured cards for Computing and Information Technology, Business, Engineering, Education, Health Sciences, and Humanities and Social Sciences.
- [x] Each programme card contains an academic focus, example programmes, and an accessible action to learn more.

## 5. Campus Life content
- [x] The Campus Life route covers the library, computer laboratories, sports and recreation, accommodation, and student clubs and activities.
- [x] Facilities include practical sample details such as opening hours, access, and joining/application guidance.

## 6. Contact experience
- [x] The Contact Us route displays sample email, telephone, location details, and a visual contact form with required name, email, and message fields.
- [x] Client-side validation and a friendly confirmation state work entirely in the browser without a backend.

## 7. Responsive and accessible implementation
- [x] Layouts are mobile-first and adapt navigation, cards, typography, spacing, and content presentation across screen sizes.
- [x] The implementation uses semantic landmarks, logical heading structure, labelled fields, accessible contrast, keyboard-friendly controls, and visible focus states.
- [x] Each route sets a descriptive browser title and the route manifest covers all page paths.

## 8. Lightweight production handoff
- [x] The site runs with a small Node static server, has no login, database, authentication, or backend dependency, and includes a build configuration for static publication.
